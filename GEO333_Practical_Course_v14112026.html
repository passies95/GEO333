Course overview

  • This practical introduces Geography students to programming to equip them with the skills and competencies in:
  1. Formulating a geographical problem and translating it into a GIS workflow.
  2. Understanding fundamental programming concepts and writing simple Python programs
  3. Using Python libraries to acquire and process spatial data.

  5. Creating and querying a PostgreSQL/PostGIS database using SQL.
  6. Applying select geoprocessing and spatial analysis methods
  7. Developing a collaborative interactive 2D campus map using Python-based tools and documenting the procedures

Introduction to GIS Programming

  • GIS is used in virtually every sector of society including Transportation, Health, Agriculture, Urban Planning, Environmental Management, and many more.
  • GIS programming is the process of using a programming language to automate GIS operations, manage spatial data and develop GIS applications.

Systems: Many components working together through a set of rules/ procedures to achieve a common goal i.e. of linking what we know to the where.

  • It is a core component of a GIS system
  • It provides procedures/steps, tools and libraries for the development of GIS applications and the automation of GIS workflows.

Semester project specification

Project scenario

The University of Lagos requires an accessible campus information map through which students, visitors and other users can identify buildings, roads, departments and selected facilities.What is the minimum application functionality that will satisfy the needs of the users?

Minimum application functions

The final application should:

  • Display the campus boundary;
  • Display building footprints, roads and selected facilities based on functional categories e.g bus station, library, cafeteria, sports complex, etc.;
  • Allow users to click a building and view its attributes including name, category, number of floors and associated departments, photo
  • Provide a basic search based on the variable such as department, faculty, building name or facility type or function type e.g Electric Bus station
  • Allow users to switch map layers on and off.
  • Present a clear title, legend or layer key, and source information
  • Route finding. Allow the user to input their current location or autimatically pick their location and find routes based on walkable paths, transport options within the universtiy

Suggested campus data model

Designing the campus database requires identifying the spatial and non-spatial entities, their attributes and relationships. The following is a suggested data model:

Layer Geometry Important fields
buildings Polygon building_id (unique), building_name, category, description
building_entrances Point entrance_id (unique), building_id (foreign key), entrance_name, entrance_type, is_public, accessibility_note
pedestrian_paths Line path_id, path_type, surface, accessible, notes
roads Line road_id, road_name, road_type
facilities Point or polygon facility_id, facility_name, facility_type

Digitise entrance points at the actual pedestrian-access location, not at the building centroid. Where a building has several entrances, map each one separately and link all of them to the same building_id. Record whether an entrance is public, staff-only, restricted or accessible where that information can be verified.

For routing, pedestrian paths should form a connected network. Entrance points should be connected or snapped to the appropriate pedestrian path, using a documented tolerance and checking the result visually.

Data preparation: cleaning tabular records for GIS

Purpose and scope

During this week Students need to understand the structure and quality of tabular data and prepare a clean CSV file for use in QGIS. QGIS will be the main environment for joining, filtering, summarising and analysing the data in subsequent weeks. Other Python libraries such as Pandas and GeoPandas, R packages and database tools that can perform similar tasks outside a desktop GIS will be mentioned, but students will not be required to learn those additional toolkits in this practical.

Learning outcomes

Students should be able to:

  • Explain a CSV file as a table of records and fields.
  • Inspect column names, data types, missing values and duplicate rows.
  • Identify inconsistent spellings, spaces, categories and identifiers.
  • Clean a supplied table using a spreadsheet editor or a text editor.
  • Save a consistent CSV with a clear encoding and field structure.
  • Explain how the cleaned CSV will be imported into QGIS and joined to spatial features using a common key.

Concepts

  • Records, fields, rows and columns.
  • CSV delimiters, headers, quotation marks and character encoding.
  • Missing, invalid and duplicate values.
  • Stable identifiers and join keys.
  • Data dictionary and provenance.
  • Difference between cleaning a table and spatial analysis.

Tutor-led demonstration

  1. Open a supplied campus_departments_raw.csv in Google Sheets or a spreadsheet application.
  2. Identify the header row and explain that each row represents one record.
  3. Inspect inconsistent faculty names, trailing spaces, duplicate department records and blank building IDs.
  4. Explain which issues can be corrected from an authoritative source and which must be flagged for verification rather than guessed.
  5. Standardise field names (for example department_id, department_name, faculty_id, building_id).
  6. Remove only confirmed duplicate rows; do not delete records merely because two names look similar.
  7. Save as CSV UTF-8 and reopen the saved file to check that columns and special characters remain intact.

Guided exercise

Students receive a deliberately imperfect table containing department names, faculty codes and building identifiers. They prepare a cleaned copy, maintain the original raw file, record each correction and create a short data dictionary explaining the fields.

Assingment

Each group prepares one cleaned non-spatial table that can later be joined to campus spatial data. The join key must match the identifier in the spatial layer exactly.

Expected output

  • Original raw CSV retained unchanged.
  • Cleaned UTF-8 CSV.
  • Short data dictionary.
  • Cleaning log listing changes and unresolved issues.

Reflection questions

  • Why should raw data be preserved?
  • Why is a stable ID usually safer than joining on a name?
  • Why should an unknown value remain unknown rather than be invented?

GIS data management and processing across QGIS and PostGIS

Purpose and scope

QGIS and PostGIS are the principal tools. Students should see that filtering, selecting, reprojection, joining, validation and exporting are not isolated to one software package: GIS applications and programming/database environments implement many of the same established spatial concepts and operations. The aim is to understand the method and its inputs/outputs, not to learn another library. GeoPandas may be shown briefly by the tutor as an example of doing similar work from Python, but it is not a required student tool or assessment requirement.

Learning outcomes

Students should be able to:

  • Open and inspect the approved GeoPackage in QGIS.
  • Inspect layer geometry, fields, feature count and CRS.
  • Select and filter features by attribute and location.
  • Reproject a layer appropriately and explain why the CRS matters.
  • Join a cleaned CSV table to a spatial layer using a stable key.
  • Export an approved layer to a new GeoPackage and import it into PostGIS.
  • Recognise that comparable operations can be carried out through SQL or Python libraries without needing to learn those toolkits now.

Concepts

  • Layer, feature, geometry and attribute table.
  • Attribute query versus spatial query.
  • Select by expression and select by location.
  • Join key and one-to-many relationship.
  • CRS transformation versus assigning a CRS.
  • GeoPackage as a portable SQLite-based spatial container.
  • PostGIS as a spatial database extension to PostgreSQL.
  • Interoperability: equivalent concepts and data formats across tools.

Tutor-led activities

  1. Open the master GeoPackage in QGIS and inspect the layer properties.
  2. Open the attribute table; identify feature count, fields and data types.
  3. Demonstrate an attribute filter, such as selecting buildings where category = 'Academic'.
  4. Demonstrate Select by Location, such as selecting facilities within the campus boundary.
  5. Demonstrate a table join from the cleaned Week 4 CSV using building_id or another agreed key.
  6. Explain the difference between assigning a CRS label and actually reprojecting coordinates. Use the project CRS approved for the campus data and explain when a projected CRS is needed for metric analysis.
  7. Export the checked layer to a new GeoPackage, preserving the original.
  8. Demonstrate loading the same layer into PostGIS and viewing it in QGIS, highlighting that the data and operation concepts are interoperable across applications.
  9. Briefly show (do not require students to reproduce) that a Python library such as GeoPandas can read a GeoPackage and apply similar filtering. Explain that this is an alternative workflow, not another core course stack.

Guided exercise

Students filter the buildings layer, join the cleaned table, identify records with no matching join key, and export a checked result. They compare the number of features before and after each operation and write down why records were excluded or unmatched.

Assingment

Each group prepares a verified buildings layer with its agreed attributes, joins available department information, and imports the approved layer into the group’s PostGIS schema (or follows the tutor’s shared demonstration where individual access is not available).

Expected output

  • QGIS project with the relevant layers and joins.
  • Checked GeoPackage export.
  • PostGIS copy of the approved layer, where access is available.
  • Short interoperability note naming equivalent QGIS, SQL or Python operations.

Reflection questions

  • What is the difference between an attribute selection and a spatial selection?
  • Why can a join fail even when two tables appear to contain the same names?
  • Why should a CRS be checked before measuring distance or area?
  • What does interoperability mean in a GIS workflow?

Spatial analysis and geoprocessing using QGIS and PostGIS

Learning outcomes

Students should be able to:

  • Translate a campus question into a suitable spatial operation.
  • Run area, buffer, clip, intersection, dissolve, distance and spatial join operations in QGIS Processing.
  • Run or interpret selected equivalent PostGIS spatial SQL functions.
  • Check units, CRS, geometry validity and the reasonableness of outputs.
  • Explain what a spatial result means and what it does not establish.

Core operations and campus questions

Operation Campus question QGIS tool or method PostGIS equivalent
Area What is each building’s footprint area? Field Calculator / $area with suitable CRS ST_Area
Buffer Which buildings are within 100 m of a road? Buffer, then Select by Location ST_Buffer, ST_Intersects
Clip Which features fall inside the campus boundary? Clip ST_Intersection or spatial filter
Intersection Which buildings overlap a study zone? Intersection ST_Intersection
Spatial join Which facility is closest to or within a building/zone? Join attributes by location ST_Intersects, ST_DWithin
Distance What is the straight-line distance between selected points? Distance matrix / distance to nearest hub ST_Distance
Dissolve What is the combined area of a set of zones? Dissolve ST_Union / ST_UnaryUnion

Tutor-led activities

  1. Discuss a geographical question and identify the input layers, operation, parameters and expected output.
  2. Demonstrate calculating building area. Confirm that the layer uses an appropriate projected CRS with metre units before interpreting area in square metres.
  3. Buffer a selected campus road by a stated distance, then select buildings intersecting the buffer.
  4. Clip a facilities layer to the campus boundary.
  5. Run a spatial join to associate facilities with a campus zone.
  6. Compare one QGIS result with a tutor-prepared PostGIS query. Explain the purpose of functions such as ST_Area, ST_Buffer, ST_Intersects and ST_DWithin without requiring advanced SQL.
  7. Inspect outputs for invalid geometries, unexpected counts, units and misleading interpretations.

Example PostGIS query

SELECT
    building_id,
    name,
    ST_Area(geom) AS area_square_units
FROM campus.buildings;

The result is only interpretable as square metres if the geometry is in a suitable projected CRS measured in metres. The tutor must verify the actual campus CRS and field names before class.

Guided exercise

Students complete two QGIS analyses from a supplied set of campus questions, record parameters and export outputs to the group’s approved GeoPackage. They compare one result with the tutor’s PostGIS query or result table.

Assingment

Each group selects two questions relevant to campus users, completes the analysis, and writes a short interpretation including limitations. For example, proximity to a road does not prove that a building entrance is accessible from that road.

Expected output

  • Two QGIS Processing outputs.
  • A processing record showing input layers, CRS, parameters and output.
  • One comparison with an equivalent PostGIS spatial query.
  • A short geographical interpretation and limitations statement.

Reflection questions

  • Why does a buffer distance depend on the coordinate system and units?
  • Does a straight-line distance represent walking distance?
  • How can a spatial operation produce a valid output that is still misleading for the question being asked?

Basic SQL examples

Create a simple table:

CREATE TABLE buildings (
    building_id INTEGER PRIMARY KEY,
    building_name VARCHAR(100),
    building_type VARCHAR(50),
    floors INTEGER
);

Retrieve all records:

SELECT *
FROM buildings;

Retrieve academic buildings:

SELECT building_name
FROM buildings
WHERE building_type = 'Academic';

Count buildings:

SELECT COUNT(*)
FROM buildings;

Calculate polygon area once the spatial geometry has been imported:

SELECT
    building_name,
    ST_Area(geom) AS area
FROM buildings;

The area units depend on the geometry’s coordinate reference system. Use an appropriate projected CRS or an explicitly chosen geography calculation.

Connecting Python to PostgreSQL/PostGIS

Learning outcomes

Students should be able to:

  • Identify the purpose of host, port, database, username and password.
  • Execute a simple SQL query from Python using a database driver.
  • Read and display returned records.
  • Protect credentials and distinguish a read-only query from an edit.

Concepts

  • Database connection and connection parameters.
  • Database driver (psycopg).
  • SQL query execution and returned rows.
  • Error handling and closing a connection.
  • Credentials, environment variables and least-privilege access.

Demonstration

Use a tutor-controlled read-only account and a small query. The tutor should supply connection values privately; never place a real password in a script committed to GitHub. The following is a teaching pattern, not a working connection string:

import psycopg

connection = psycopg.connect(
    host="HOST_FROM_TUTOR",
    port=5432,
    dbname="DATABASE_NAME",
    user="READ_ONLY_USER",
    password="PASSWORD_SUPPLIED_PRIVATELY"
)

try:
    with connection.cursor() as cursor:
        cursor.execute(
            "SELECT building_id, name FROM campus.buildings LIMIT 10;"
        )
        for row in cursor.fetchall():
            print(row)
finally:
    connection.close()

Explain each step: import the driver, connect, create a cursor, execute SQL, fetch rows and close the connection. If the class cannot install or connect the driver reliably, the tutor can demonstrate the script while students practise the equivalent query in pgAdmin and QGIS. The course does not require students to build a backend server.

Guided exercise

  1. Open the tutor’s sample script in VS Code.
  2. Identify the connection parameters without exposing the password.
  3. Run a read-only query against the prepared database.
  4. Change the selected fields and the LIMIT value.
  5. Compare the result with the same query in pgAdmin.
  6. Explain why the result is a table of records and why geometry-aware operations are more naturally performed in QGIS or PostGIS.

Assingment

Each group prepares one Python script that retrieves a small set of building attributes from PostGIS. The group documents the query and explains how QGIS, SQL and Python can access the same authoritative dataset using different interfaces.

Expected output

A simple Python database-reading script, a saved SQL query and a short explanation of the data flow. No Pandas or GeoPandas dependency is required.
